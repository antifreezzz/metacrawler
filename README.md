# 🎮 Metacrawler

**Metacrawler** — автономный сервис для регулярного парсинга, аналитики и мониторинга видеоигр с сайта Metacritic с использованием OpenAI-совместимых LLM, векторного поиска похожих игр и анализа YouTube-летсплеев.

---

## 🚀 Возможности

1. **Автоматический сбор по расписанию (1 раз в час)**:
   - **Первый запуск в сутках**: сбор первых 20 игр из раздела [New Releases](https://www.metacritic.com/game/) без добора.
   - **Последующие запуски**: сбор строго по пагинации раздела [See All](https://www.metacritic.com/browse/game/all/all/all-time/new/?page=N) (по одной странице в час, без добора с других страниц).
   - **Новый день**: автоматический сброс цикла и пагинации обратно на New Releases.
   - **Кулдаун**: настраиваемая задержка с джиттером между запросами для защиты от rate limit.
   - **Полные списки отзывов**: помимо главной страницы игры собираются подстраницы `/critic-reviews/` и `/user-reviews/`; отзывы привязываются к платформе из карточки отзыва.
   - **История оценок**: изменения Metascore/Userscore сохраняются в `score_history` и отображаются дельтой на карточке игры.
   - **Параллельный анализ**: LLM-резюме платформ (до 3 одновременно) и эмбеддинг/YouTube выполняются параллельно; резюме не пересобирается, если отзывы не изменились.
2. **Обход WAF / Cloudflare**:
   - HTTP-клиент на базе `github.com/bogdanfinn/tls-client` с профилем `Chrome 133` и реалистичными заголовками.
3. **Платформенная модель данных и дедубликация отзывов**:
   - Оценки (`Metascore`, `Userscore`) и отзывы жестко привязаны к конкретной платформе (PC, PS5, Xbox Series X, Switch и др.).
   - Полная дедубликация отзывов по уникальному хешу `UNIQUE(game_platform_id, content_hash)`.
4. **AI-анализ отзывов (LLM)**:
   - Раздельный анализ мнений критиков и игроков:
     - `critic_pros` / `critic_cons` (что нравится и что не нравится критикам).
     - `user_pros` / `user_cons` (что нравится и что не нравится игрокам).
   - Резюме генерируются на русском языке (несмотря на англоязычные отзывы).
   - **Перевод описания игры** на русский с кэшированием в `games.description_ru`; оригинал показывается сворачиваемым блоком. При недоступности LLM перевод не выдумывается - отдаётся оригинал.
   - Поддержка любой OpenAI-совместимой модели (настраивается через `.env`) с fallback-режимом при отсутствии ключа.
5. **Векторный поиск похожих игр**:
   - Генерация эмбеддингов описания игры и хранение векторов в SQLite (BLOB).
   - In-memory расчет косинусного сходства (`Cosine Similarity`) и подбор Top-5 похожих игр.
6. **YouTube-анализ летсплеев (Доп. часть 1)**:
   - Поиск самого популярного летсплея на YouTube через публичный эндпоинт `/results`.
   - Отсев трейлеров и промо-роликов (маркеры в заголовке + минимальная длительность ролика), чтобы в выборке оставались именно летсплеи.
   - Прямой бесплатный сбор субтитров через `/api/timedtext` без официального API ключа.
   - Заключение по рассказу блоггера через LLM с прямой ссылкой на ролик в карточке игры.
7. **Веб-интерфейс & Real-time мониторинг (Доп. часть 2)**:
   - **Каталог (`/`)**: быстрый живой поиск по названию (debounce 300ms), фильтр по платформам, сортировка по рейтингу.
   - **Карточка игры (`/games/{slug}`)**: полная информация, плеер/ссылка трейлера, оценки по всем платформам с дельтами изменений, плюсы/минусы критиков и игроков, YouTube-обзор, похожие игры.
   - **Дашборд мониторинга (`/monitoring`)**: счетчики, статусы воркеров, живой терминал логов через HTMX SSE.
   - **Пульт ручного запуска**: принудительный запуск New Releases, следующей страницы каталога или произвольной страницы по номеру.
   - **Пересбор игры по частям**: на карточке игры доступен выбор, что обновить (сбор с Metacritic, LLM-резюме, перевод описания, YouTube-летсплей, эмбеддинг); ход фонового пересбора показывается по статусу с автополлингом.
8. **RSS-фид (`/rss`)**: последние 30 добавленных игр, готово для подписки в ридерах и Telegram-ботах.
9. **Превью ссылок**: Open Graph и twitter:card теги для красивых карточек в Telegram/Discord/X (favicon в комплекте).
10. **Эксплуатация**: `/healthz` (liveness), `/readyz` (readiness с проверкой БД), `/metrics` (Prometheus), структурные JSON-логи с `X-Request-ID`.

## 🛠 Технологический стек

- **Язык**: Go 1.24+
- **База данных**: SQLite pure Go (`modernc.org/sqlite`, CGO=0)
- **HTTP / WAF bypass**: `github.com/bogdanfinn/tls-client`
- **Парсинг**: `github.com/PuerkitoBio/goquery`, `github.com/tidwall/gjson`
- **Планировщик**: `github.com/robfig/cron/v3`
- **Фронтенд**: Go `html/template` + Tailwind CSS v4 (CDN) + HTMX 2.0 + HTMX SSE extension
- **LLM & Embeddings**: OpenAI-compatible client
- **Контейнеризация**: Multi-stage Dockerfile на базе Alpine Linux

## ⚙️ Конфигурация (`.env`)

Скопируйте `.env.example` в `.env`:
```bash
cp .env.example .env
```

Параметры:
```ini
```ini
PORT=8079
DB_PATH=data/metacrawler.db
CRON_SCHEDULE=0 * * * *
CRAWL_DELAY_MIN_MS=2000
CRAWL_DELAY_MAX_MS=4000
LLM_TIMEOUT_SECONDS=120

# OpenAI-совместимый API (опционально, при отсутствии ключа работает fallback)
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini
EMBEDDING_MODEL=text-embedding-3-small
```

Пароль администратора (минимум 8 символов) и `SESSION_SECRET` (минимум 32) обязательны:
сервис не стартует со слабыми или отсутствующими секретами. Для локальной разработки
можно выставить `ALLOW_INSECURE_DEFAULTS=true`.

## 🐳 Запуск в Docker

Сборка и запуск через Docker Compose:
```bash

```
Или напрямую через Makefile:
```bash
make docker-up
```
База данных SQLite сохраняется в volume `./data/metacrawler.db`.

## 💾 Бэкапы и восстановление

Сервис периодически создает консистентные снапшоты БД (SQLite `VACUUM INTO`) в
`BACKUP_DIR` (по умолчанию `<каталог БД>/backups`), храня последние `BACKUP_RETENTION`
штук. Интервал задается `BACKUP_INTERVAL_HOURS` (по умолчанию 24ч), включение -
`BACKUP_ENABLED`.

Восстановление:
```bash
docker compose down
cp data/backups/metacrawler-YYYYMMDD-HHMMSS.db data/metacrawler.db
rm -f data/metacrawler.db-wal data/metacrawler.db-shm
docker compose up -d
```
Проверьте `/readyz` и логи запуска.

## 🌿 Рабочий процесс (ветки и Pull Request)

Прямой пуш в `main` запрещён. Каждая единица работы ведётся в feature-ветке, по завершении открывается Pull Request:

```bash
git checkout -b feat/my-change
# ... правки, тесты ...
git push -u origin feat/my-change
gh pr create --base main --fill
```

PR сливается в `main` только после зелёных тестов (`go test -race ./...`, `go vet ./...`). Подробные правила - в `agents.md`.
